# Agent Instructions

## Mission

Build this monorepo as a reliable, maintainable game-development workspace.

## Working rules

- Read the relevant document in `docs/` before implementation.
- Make focused changes; avoid unrelated cleanup.
- Keep plans, architecture, and code synchronized.
- Prefer reusable systems over project-specific exceptions.
- Keep configuration data, assets, and source code separated when practical.
- Add focused tests for behavior that is introduced or changed.
- State validation commands and results honestly.

## Planning

Before implementation, create or update:

- `docs/game-design.md` for the player experience and feature scope.
- `docs/game-plan.md` for milestones and task sequencing.
- `docs/architecture.md` for technical decisions and module boundaries.

## Completion criteria

A task is complete only when:

1. The requested behavior is implemented.
2. Relevant tests pass or the limitation is explicit.
3. Documentation and configuration stay consistent with the code.
4. No temporary debug files or accidental credentials remain.
